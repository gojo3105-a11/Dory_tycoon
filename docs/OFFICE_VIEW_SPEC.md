# 관제 화면 - 부서 사무실 뷰 명세

`Reports/dashboard.html`(생성기: `AI_GAME_COMPANY/company/orchestrator/dashboard.py`)에
새 섹션 하나를 추가한다. 연동된 AI를 **회사 부서에 앉은 캐릭터**로 그리고, 각 캐릭터의
움직임이 그 AI의 실제 상태를 나타낸다.

이 문서는 Claude가 쓴 명세이고, 구현은 Codex가 한다 (`CODEX-OFFICE1`).
사용자 지시에 따라 모든 코딩은 Codex 몫이다.

## 왜 만드는가

지금 로스터는 정확하지만 표다. 여덟 줄을 읽어야 "지금 일할 수 있는 건 한 명"이라는 사실이
들어온다. 사무실 그림은 그걸 **한눈에** 만든다 - 빈 책상과 앉아서 타이핑하는 사람의 차이는
읽지 않아도 보인다.

그래서 이 뷰의 성공 기준은 "귀엽다"가 아니라 **애니메이션이 상태를 전달하는가**다.
장식으로 움직이는 캐릭터는 이 명세를 만족하지 않는다.

## 데이터 출처

새로 읽는 파일은 없다. 이미 있는 `Snapshot.agents`(각각 `name`, `role`, `state`, `detail`)를
그대로 쓴다. `state`는 `ready` / `gated` / `blocked` / `unknown` 네 값이다.

부서는 에이전트 이름의 **접두사**로 정한다. 이름에 모델 id가 붙기 때문이다
(예: `Ollama · gemma4:26b`). `dashboard.py`에 매핑 표를 하나 둔다:

| 이름 접두사 | 부서 | 부서 id |
|---|---|---|
| `Claude Code` | 기획개발실 | `dev` |
| `Codex CLI` | 기획개발실 | `dev` |
| `Gemini` | 디자인실 | `design` |
| `Stable Diffusion` | 디자인실 | `design` |
| `Qwen-Image` | 디자인실 | `design` |
| `Ollama` | 사내 연구소 | `lab` |
| `Blender` | 3D 모델링실 | `modeling` |
| `유료 API` | 외주 | `outsource` |

- 표에 없는 이름은 **버리지 말고** `기타`(`etc`) 부서에 넣는다. 나중에 AI가 추가될 때
  화면에서 조용히 사라지면 안 된다.
- 한 부서에 여러 명이 앉을 수 있다 (디자인실은 최대 3명).

## 부서 배치

위에서 내려다본 평면도. 건물 윤곽 안에 방 네 개, **외주는 건물 밖**에 둔다 - 계약이 없는
상태를 배치로 말한다.

```
┌─────────────────────────── 건물 ───────────────────────────┐
│  기획개발실 (dev)              디자인실 (design)          │
│  Claude, Codex                 Gemini, SD, Qwen           │
│                                                            │
│  사내 연구소 (lab)             3D 모델링실 (modeling)     │
│  Ollama                        Blender                     │
└────────────────────────────────────────────────────────────┘
        외주 (outsource) - 건물 밖, 점선 테두리
        유료 API
```

각 방에는 방 이름과 `n명 중 m명 작업 중` 카운트를 붙인다.

## 상태별 동작 (핵심)

| state | 라벨 | 캐릭터 | 움직임 | 책상/소품 |
|---|---|---|---|---|
| `ready` | 작업 가능 | 정상 채색 | 타이핑 - 양 팔뚝이 번갈아 상하로, 어깨가 미세하게 들썩 | 모니터 켜짐, 커서 깜빡임 |
| `gated` | 대기 중 | 정상 채색 | 서 있고, 머리 위 `!` 말풍선이 천천히 커졌다 작아짐 | 모니터 대기 화면 |
| `blocked` | 사용 불가 | 채도 없음 (회색조) | 움직이지 않음 | 모니터 꺼짐, 의자가 책상에서 밀려나 있음 |
| `unknown` | 확인 불가 | 점선 실루엣, 반투명 | 아주 느린 페이드 인/아웃 | 책상만 있고 소품 없음 |

색은 대시보드에 이미 있는 토큰을 쓴다: `--ok` / `--gate` / `--blocked` / `--unknown`.
새 색을 만들지 않는다.

## 캐릭터 아트

**v1은 에셋 없이 동작해야 한다.** 절차적 인라인 SVG로 그린다 - 머리, 몸통, 팔 두 개 정도의
단순한 형태면 충분하다. 이미지 파일을 새로 받거나 라이선스를 추가하지 않는다.

부서마다 캐릭터 색을 달리해서 방을 구분한다. 나중에 Gemini가 실제 캐릭터 아트를 만들면
SVG를 `<img>`로 교체할 수 있게, 캐릭터 렌더 함수를 한 곳에 모아 둔다
(`_character_svg(department, state)` 같은 형태).

## 기술 제약

- **외부 라이브러리 금지.** CSS 키프레임 + 인라인 SVG만. 애니메이션 JS 루프를 돌리지 않는다
  (배터리를 먹고, 이 페이지는 오래 열어두는 화면이다).
- **두 테마 모두 동작.** 색은 반드시 `var(--토큰)`으로. `@media`나 `[data-theme]` 블록
  안에서만 정의되는 색을 만들면 안 된다 - 대시보드에 이미 있는 규칙이다.
- **`prefers-reduced-motion: reduce`면 모든 움직임을 멈춘다.** 이때도 상태는 색과 자세로
  읽혀야 한다 - 움직임이 유일한 신호이면 안 된다.
- **정적 파일에서도 보인다.** 서버 없이 열어도 동작해야 한다 (제어판과 달리 이건 표시 전용).
- 가로 스크롤을 만들지 않는다. 좁은 화면에서는 방을 세로로 쌓는다.
- 캐릭터에 `title`/`aria-label`로 "이름 - 상태"를 넣는다. 그림만으로 읽히지 않는
  사용자에게도 정보가 가야 한다.
- 캐릭터를 클릭하면 아래 로스터의 해당 줄로 이동한다 (`#agent-<slug>` 앵커).

## 하지 말 것

- 상태와 무관하게 모두 똑같이 움직이게 하지 않는다. 그러면 이 섹션은 장식이다.
- `blocked`를 웃는 얼굴로 그리지 않는다. 화면이 상태를 거짓으로 말하게 된다.
- 실제로 없는 AI를 채워 넣어 방을 예쁘게 만들지 않는다. 빈 방은 빈 방으로 그린다.
- 근거 없는 수치(작업 진행률 %, 가동률 등)를 만들어 붙이지 않는다. 이 대시보드의 규칙은
  "근거 없으면 확인 불가"다.
